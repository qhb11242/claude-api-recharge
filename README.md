# Claude API 20 美元充值：先分清这笔钱买的是什么，再决定怎么付

搜「Claude API 20 美元充值」的人，卡点通常不在"想不想充"，而在两个具体问题：这 20 美元到底进的是哪个账户，以及手上没有能过风控的国际卡时这钱怎么交出去。

先说最容易踩的坑：Claude 有 **两套完全独立的账单**。claude.ai 里的 Claude Pro 是每月 20 美元的订阅，管的是聊天应用、Projects、Claude Code 的订阅额度；而 Claude API 走的是 Console 里的 **prepaid usage credits**（预付使用额度），这笔钱只覆盖 API 调用、Workbench 和用 API Key 跑 Claude Code。买 Pro 不会给你 API 额度，充 credits 也不会解锁聊天会员。名字像、价格都是 20 美元，但两笔钱互不相通。

## 20 美元在 Console 里能买到什么

Claude 官方帮助中心写得很直白：API 和 Workbench 采用预付额度计费，**先买额度再调用**。余额耗尽后，在补充之前 API 和 playground 都无法继续使用。几个会直接影响你决策的细节：

- **购买金额有快捷档位**：官方购买弹窗提供 $5 / $20 / $100 / 自定义，$20 恰好是页面上的推荐档位。第一次验证用途，这个数字是合理的。
- **credits 一年过期，且不退款**。条款写明自购买日起一年失效，过期日期不能延长，所有额度购买均不可退款。所以没必要一次性囤一年的量。
- **失败的请求不收费**。只对成功的 API 调用和完成的任务计费。但要注意：客户端在即将成功的请求中途断开或超时，这笔请求仍然会被计费。
- **税是另算的**。有开发者记录的实测流程里，选 $20 额度、填写账单地址后，汇总显示额度 $20.00、预估税 $2.00、合计 $22.00。具体税额跟着账单地址走，不是固定值。
- **支付方式只认卡**。官方接受的付款方式是信用卡和借记卡，明确不接受 PayPal、Venmo 这类第三方支付通道；用了不支持的付款方式，交易大概率直接被拒。

## 官方充值流程，照着点就行

1. 用管理员或计费角色登录 Console，进入 **Settings → Billing**。
2. 点「购买额度」，选择金额（$5 / $20 / $100 / 自定义），展开账单地址并填写。
3. 填卡信息。账单地址要和卡片登记的地址对得上，这是后续被拒最常见的来源之一。
4. 核对汇总金额（额度 + 预估税）后确认购买，额度立即到账。
5. 回到 API Keys 页面创建密钥，**密钥只在生成后的弹窗里完整显示一次**，当场复制保存。

> 如果你的目标只是判断 Claude 适不适合接进项目，先充 $20 跑几组真实请求，比一次性充大额更有信息量。额度用不掉还会过期，这钱不是存款。

Billing 页面上还有一个很值得打开的开关：**auto-reload**（自动充值）。设置一个最低余额阈值和补充金额，余额跌破阈值就自动买额度。生产环境因为余额归零而接口中断，是最没必要发生的一类事故。

关于额度上限还有一个常被忽略的点：Anthropic 的用量等级（usage tiers）跟着**累计购买金额**走，等级越高，每分钟请求数、每分钟 token 数和月度消费上限越高。第三方整理过的公开资料显示，Tier 1 对应的是较低门槛（约 $5 起步的存款、$100 月度用量），把累计购买做到 $40 会升到 Tier 2，月度用量上限跳到 $500 一档。这些数字会随官方政策调整，充值前建议在 Console 的 Limits 页面确认当前值——它决定的不只是"能花多少"，还有"能不能跑起来"。

## 国内用户真正会卡住的三个地方

- **卡被拒**。国内银行发行的外币卡在海外订阅和 API 场景里经常过不去，原因不一定是余额，而是发卡地区、账单地址、IP 环境综合风控的结果。
- **虚拟卡维护成本高**。开卡费、充值手续费、卡段是否被支持、续费是否成功，每一项都要自己盯着。用得顺的时候很省事，出问题时排查链条很长。
- **地区与网络环境**。注册、支付、调用三段都可能触发环境检测，换卡换地址未必解决问题，有时反而触发更多风控。

如果你已经有稳定可用的国际卡，官方直充就是最干净的路，不用考虑别的。问题在于没有这条路的人不少。
